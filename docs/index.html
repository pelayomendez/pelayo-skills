Flows

You type a flow. Each one chains small skills in order and stops for you where a decision is yours.

/supportBugs piling up in a queue. Takes each from report to released: qualify, confirm the cause with a fresh agent, fix and review with workers, check in a controlled browser, ship, check again on the test environment, close.
/mr-reviewMRs waiting for review, yours and your team's. Reviews each at its current head and stops for you on every one. Nothing is pushed, merged or posted without your word.
/backlogA backlog nobody trusts any more. Proposes what can close, with evidence, and ranks the rest by value, urgency and size (WSJF) inside the dependency graph.
/night-shiftTickets ready and a night ahead. One decision round before you leave, then queue → fix → verify → review → browser check → merge, and a morning report.
/ambient-companionA day of agents running while you do something else. Watches your work's event streams, delegates and checks, and brings you only the decisions.

Need only one job (check a claim, review one MR, hand off)? Ask for it and the agent picks the skill.

Where it stops for you

Nothing is merged, pushed or posted under your name unless you said so, in the chat or in your charter: a plain-text file of what the agent may do alone, must ask first, or never does. With an empty charter, it asks every time.

Bring your own skills

Some steps are slots: plug in the skill you already trust and the flow keeps its stops, reports and checks around it. Unset slots use ours.

implementWrites the fix or feature in a worker.
reviewReviews a change; the flow still verifies each finding.
browser-checkChecks the change in a controlled browser.
# ~/.claude/slots.md
- implement: my-tdd-skill
- review: my-code-review-skill

Skills

Small one-job skills the agent reaches for on its own, inside a flow or outside one.

charterYour permissions file: what the agent may do alone, must ask first, or never, per scope, in your own words.
verify-claimA fresh agent checks another agent's claim, seeing only the claim and its evidence.
delegate · watch · handoffBrief and launch a worker safely, watch a pipeline or MR until it settles, and leave a handoff another session can resume.
qualify · ticket-pick · tracker-moveCheck a bug is ready for an agent, take a ready ticket into work, and move it on the status board.
review-change · ui-checkReview one MR at its current head, read-only; check a fix in a controlled browser, never yours.
snapshot-backlog · prune-backlog · order-backlogRead a backlog once, propose what can close with evidence, rank the rest inside the dependency graph.
reap-procs · tidyFind what is eating the machine after agent sessions and stop only what nobody owns; a weekly and monthly tune-up of your agent setup.
high-level-communicationAlways on. Report like a senior engineer to another: why, what changed, impact, trade-offs, risks, next steps.

Install

/plugin marketplace add pelayomendez/yatsude
/plugin install yatsude@yatsude
/plugin install flow-map@yatsude   # optional pane

Or npx skills@latest add pelayomendez/yatsude to copy them into a project. Install one way, not both.

Needs: Claude Code; your tracker's CLI or MCP (for Jira, acli) and your forge's CLI (glab or gh) for the flows that touch tickets and MRs; a controlled-browser MCP (e.g. chrome-devtools) for browser checks. Details in the README.

FAQ

Does it push or merge without me? Only what your charter grants for that flow, never what the table above marks as never.
GitHub or GitLab, Jira or something else? The flows name the step, not the tool; your flow config says which CLI or MCP to use.
How do I start? /backlog <epic> only reads. Then copy the example flow config and try /mr-review <MR URL>.

The name is Japanese: yatsude (八つ手), "eight hands".
